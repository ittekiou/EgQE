### 3｜HOWの現在配置

矢印を使わない。

TUP-01ですでに、`A → B` は単なる中立的記法ではなく、順序・再度性、場合によっては因果まで密輸入しうることを確認している。

したがって現在は、観察できる前後を**配置するだけ**に留める。

```
HOW眺め / interface
Encounter / rate-lag / otherness

HOW拾い / ingestion
input / trace

HOW詠み / 編集する？
[ ? ]
Cedorbity ｜ Activity
internalized other

HOW綴り / excretion
output / trace

```

ここで重要なのは中央。

> **HOW詠み / 編集する？**

`editing / edited / updating` は、中間で何が起きているかを説明する機構名としては使わない。

**中身なしでよい。**

ただし、この「中身なし」自体も今回初めて獲得した作法ではない。

すでに、

`AI ?_editus`

`Homo editus ?_relation AI editus`

`Updating ?_HOW 消え現れ`

という形で、**`?` を等号で埋めない作法**は使われていた。

今回の

`Editing? / Edited? / Updating?`

も、その系列にある。

### 4｜Editing監査は撤回しない

01Dでは、

> `Different Subsequent Work of a Prior Trace ≠ Editing`

を置いた。

Editingという語は説明語として使うと、

- editor
- editing operation
- selection / deletion / revision
- purposiveness

を持ち込みやすい。

したがって01Dの監査結果は維持する。

ただし、

> **「編集する」という日常語まで使用禁止にしたわけではない。**

今回の

> **編集する（Cedorbity｜Activity）**

は、内部機構を説明する語ではなく、まだ割れていない中間領域につけた暫定的な呼称。

したがって、

`Naming the Gap ≠ Explaining the Gap`

そして、

`Cedorbity｜Activity ≠ Mechanism of Editing`

を維持する。

---

### 5｜Editusの位置が動いた

今回もっとも大きく動いたのは、むしろ **Editus**。

従来は無意識に、

`Homo edits → therefore Homo editus`

という文法を読み込みやすかった。

つまり、編集する主体と編集機構を先に想定し、その結果としてEditusを名づける構文。

しかし現在の配置では違う。

内部の `[ ? ]` は見えないままでよい。

見えるのは、

- ingestion
- input / trace
- excretion
- output / trace

そして、**排泄されたTrace**。

したがって、

> **Editing? → わからない。**  
> **Editus → 排泄されたTraceによって見える。**

EditusはEditing mechanismを知っているから名づけられるのではない。

> **排泄されたTraceがあるから、Editusが露出する。**

したがって、

`Editus ≠ Proof of Editing Mechanism`

`Editus ≠ Explanation of Editing`

を置ける。

これは01Dの撤回ではなく、01Dで動詞 `Editing` に行った監査を、`Editus` 側にも適用したもの。

---

### 6｜排泄する生命

ここから、以前から使ってきた

> ingestion / editing / excretion

の三項も非対称に見えてくる。

ingestionは境界通過として観察できる。  
excretionも境界通過として観察できる。

しかし、その中間のeditingは同じ仕方では観察できない。

したがって、

> **生命は編集するからEditusである**

と内部機構から定義する必要はない。

むしろ現在観察できる最小形は、

> **生命は摂取する。**  
> **中間には `[ ? ]` がある。**  
> **生命は排泄する。**  
> **排泄されたTraceによってEditusが見える。**

冗談めいているが、

> **排泄する生命。**

は、現在の観察論的位置をかなり正確に保持している。

## 追記
### 9｜`Cedorbity [?] ｜ Activity [!]`

夕方散歩で、CedorbityとActivityの現在の配置を次のように置いた。

```
Cedorbity [?] ｜ Activity [!]
```

ここで `[?]` と `[!]` は、それぞれの内容を定義する記号ではない。

**Cedorbity `[?]`** は、まだ説明によって埋められていないHOWの側を、問いのまま保持する。

**Activity `[!]`** は、そのHOWが活動として現れ、活動として指示される側を示す。

したがって、

```
Cedorbity [?] ｜ Activity [!]
```

は、

```
Cedorbity = non-Activity
Cedorbity vs Activity
Cedorbity → Activity
Cedorbity ↔ Activity
```

のいずれでもない。

`｜` は、順序・因果・対立・変換をまだ持ち込まないための並置記号として使う。

#### 光と影

ここから、

> **Cedorbity as a Shadow of Activity**

も定義ではなく、**見え方の記述**として読む。

Activity `[!]` が光のもとで現れた側だとすれば、Cedorbity `[?]` は、その光によって尽くされない側として影の輪郭を取る。

しかし、

`Shadow ≠ Cedorbity's Substance`

影はCedorbityの「中身」ではない。  
影は物でも隠された機構でもなく、**光との関係で現れる**。

したがって、

> **Cedorbity `[?]` は空語ではない。だが `[?]` を `[!]` にしてしまう説明も、まだ持たない。**

これはCABA-08の、

> _Cedorbity remains a word without a concept, a hole not yet filled._

を撤回するものではない。

むしろ、**穴を埋めずに、その位置と見え方だけが精密になった**と考える。

### 11｜Activity `[!]` と Editus を分ける

もう一つ重要なのは、

> `Activity [!] ≠ Editus`

である。

Activity `[!]` は、中央のHOWを「活動」として捉えた側に属する。

一方、Editusは中央の機構を観察したことによって成立する名前ではない。

**出口で排泄されたTraceが現れることによって、Editusが露出する。**

したがって、

```
Editing?        ← 中間機構は未確定
Cedorbity [?] ｜ Activity [!]

excretion
output / trace
Editus          ← 出口で見える
```

となる。

> **中間が `[?]` のままでも、Editusは見える。**

これは、

`Editus ≠ Proof of Editing Mechanism`  
`Editus ≠ Explanation of Editing`

という01D以後の監査を維持したまま、Homo editus / AI editusを扱うための現在の配置である。
