# TUP-DN-07｜Where Is History?

## System / Relation / Observer

### History-bearing は、どこにあるのか

> **A later configuration may not be history-free.**
> 
> **But where is its history?**

[TUP-DN-06｜「また」と「もう一度」は何が違うのか｜Recurrence / Re-occurrence ── What Makes an Again?](https://camp-us.net/articles/TUP-DN-06_Recurrence_Re-occurrence_What-Makes-an-Again.html)  

---

前稿では、

**recurrence**

と

**re-occurrence**

を分けた。

似たことが再び起きた。

それだけなのか。

それとも、以前に起きたことを経て、再び起きたのか。

そのdifferenceを、

**history-free recurrence**

と

**history-bearing re-occurrence**

として仮に区別した。

すると、次の問いが生じる。

**Historyは、どこにあるのか。**

---

# 1｜犬のhistoryはどこにある？

犬が店へ行く。

ご褒美を食べる。

翌日、自発的に店へ向かう。

昨日を経た今日だ、と言いたくなる。

では、昨日はどこにあるのか。

犬の脳か。

身体か。

神経系か。

行動傾向か。

店とのrelationか。

散歩コースか。

飼い主とのinteractionか。

それとも、昨日と今日を並べて見ている観察者の記述のなかか。

「犬のなかにhistoryがある」

と簡単に言ってよいのだろうか。

---

# 2｜AIのhistoryはどこにある？

AIの場合は、さらに露骨である。

昨日の会話をcontextとして与える。

今日の生成が変わる。

historyは、

context windowにあるのか。

token列にあるのか。

内部状態にあるのか。

外部ファイルにあるのか。

retrieval systemにあるのか。

人間が書いたpromptにあるのか。

それらを接続するsystem全体にあるのか。

どこか一か所を指して、

**Here is the history.**

と言えるだろうか。

---

# 3｜Homo sapiensのhistoryはどこにある？

人間では、

「記憶にある」

と言いたくなる。

しかし記憶とは何か。

脳内に保存された記録なのか。

身体の習慣なのか。

語彙の変化なのか。

判断傾向なのか。

ノートなのか。

写真なのか。

他者との会話なのか。

環境に配置された道具なのか。

昨日と今日のrelationを、

「history」と呼んでいるだけなのか。

ここでも、場所を一つに決めることは難しい。

---

# 4｜System

第一候補は、

**System**

である。

prior occurrenceによって、systemのconfigurationが変わる。

そのdifferenceがlater configurationに関係する。

ならば、

historyはsystemにある。

そう言いたくなる。

しかし、systemとはどこまでか。

犬の脳だけか。

身体までか。

店まで含むのか。

AIモデルだけか。

contextも含むのか。

retrievalも含むのか。

Homo sapiensの脳だけか。

ノートやスマートフォンも含むのか。

境界を変えれば、historyの所在も変わる。

すると、

**History is in the system**

という答えは、

**what counts as the system?**

という問いへ送り返される。

---

# 5｜Relation

第二候補は、

**Relation**

である。

historyは、何か一つの内部に保存されているのではない。

prior configurationとlater configurationのrelationにある。

犬と店。

AIとcontext。

人間と文章。

beforeとafter。

このあいだにhistoryがある。

そう考えれば、内部実体を置かなくて済む。

しかし、

relationにhistoryが「ある」

とはどういう意味だろう。

relationを、新しい容器にしているだけではないか。

**History is not in a thing.  
History is in a relation.**

と言った瞬間、relationをthingの代用品にしていないか。

ここでも実体化は逃げ切れない。

---

# 6｜Observer

第三候補は、

**Observer**

である。

犬の昨日と今日を並べる。

AIの昨日と今日を比較する。

人間のbefore / afterを読む。

そして、

「これはhistory-bearingだ」

と判定する。

ならば、historyは観察者が構成しているのではないか。

prior occurrenceとlater occurrenceを、一つの系列として読む。

その読みが、historyを生成する。

これは強い候補である。

しかし、問題もある。

観察者がいなければ、history dependenceは消えるのか。

犬の行動は、誰も見ていなければhistory-freeになるのか。

AIのcontextは、誰も観察しなければlater generationに関係しなくなるのか。

そうではなさそうである。

すると、

**History = Observer Construction**

とも簡単には言えない。

---

# 7｜Three Failures

三つとも失敗する。

**System**

に置くと、system boundary問題が起きる。

**Relation**

に置くと、relationを実体化する危険がある。

**Observer**

に置くと、observer-independentなhistory dependenceを説明しにくい。

では、historyはどこにあるのか。

もしかすると、問いそのものが間違っている。

---

# 8｜Where → How

**Where is history?**

と問うと、historyを何かのように扱ってしまう。

だから問いを変える。

> **How does a later configuration become describable as history-bearing?**

どこにあるか。

ではなく、

**どのような条件でhistory-bearingという記述が成立するのか。**

ここで、存在論から構文へ移る。

---

# 9｜Phenomenology

現象学的には、

問題は、historyがどこに保存されているかではない。

later Encounterが、

**Againとして現れる**

ことにある。

同じ店。

同じ文章。

同じ言葉。

しかし、二度目は一度目ではない。

二度目には、

**「もう一度」**

が現れる。

ここではhistoryは、物として見つかるのではない。

later Encounterの現れ方を変える。

少なくとも、

Homo sapiensについては、そう記述できる。

しかし犬やAIについて、

同じ現象学的記述をそのまま使ってよいかは、別問題である。

---

# 10｜Semiotics

記号論的には、問題は別の形になる。

あるsomethingが、別のsomethingを指す。

スクリーンショットが、過去のAmazon表示を指す。

足跡が、以前そこを通った何かを指す。

文章が、以前の出来事を記述する。

ここではhistoryは、

**reference**

として現れる。

しかし、

AI偽造スクリーンショットが示したように、referenceは正しいとは限らない。👉 [AP-02](https://camp-us.net/articles/TUP-AP-02_Amazon-Problem_2.html)  

何かが過去を指すことと、その過去が実際にあったことは、同じではない。

したがって、

**Reference ≠ History.**

そして、

**Sign ≠ Trace.**

少なくとも等号はまだ置けない。

---

# 11｜Causal Description

さらに第三の記述がある。

prior conditionを操作すると、later configurationの分布が変わる。

ここでは、historyは現れでもreferenceでもない。

**dependency**

として記述される。

犬。

AI。

Homo sapiens。

いずれについても、条件を適切に設定できれば、

prior configurationとlater configurationのdependencyを調べることができる。

しかし、

**Dependency ≠ Trace.**

これもTraceなしで記述できる。

---

# 12｜Three Descriptions

すると、history-bearingを少なくとも三通りに記述できる。

**Phenomenological**

Againとして現れる。

**Semiotic**

somethingがprior somethingを指す。

**Causal / Relational**

later configurationがprior conditionに依存する。

これらは、同じではない。

**Appearance ≠ Reference ≠ Dependency.**

ここを一つに潰さない。

---

# 13｜Traceは三つを束ねるのか

ここで誘惑が生じる。

Traceとは、

Appearance.

Reference.

Dependency.

これらを束ねる概念なのではないか。

しかし、それは危険である。

三つの異なる問題を、Traceという一語に押し込んだだけかもしれない。

Traceを統一概念として救う前に、

むしろ三つを分離したまま、どこでTraceという語が必要になるかを見るべきである。

---

# 14｜Dog / AI / Homo sapiens

三者を戻す。

犬では、dependencyを観察できるかもしれない。

しかし、

Againがどのように現れているかを、人間と同じ意味で記述できるかは分からない。

AIでは、referenceやdependencyを構成できる。

しかし、

Againが現象学的に成立しているかは別問題である。

Homo sapiensでは、三つすべてを記述できる場合がある。

しかし、

三つが一致するとは限らない。

「前にも見た」と感じるが、実際には初見かもしれない。

過去を正しくreferenceしているが、現在の判断にはeffectがないかもしれない。

prior exposureが判断にeffectを持っていても、本人にはAgainとして現れないかもしれない。

したがって、

**Appearance / Reference / Dependency**

は直交しうる。

---

# 15｜Amazon Again

Amazon Problemへ戻る。

本物のスクリーンショット。

偽造スクリーンショット。

スクリーンショットなし。

記憶あり。

記憶なし。

記事あり。

記事なし。

これらを、一つのTrace有無で分類しようとすると、混線する。

なぜなら、

referenceの問題と、dependencyの問題と、appearanceの問題が、別々に動くからである。

偽造画像は、false referenceを生むかもしれない。

しかしlater judgmentには、real effectを持ちうる。

そして読者には、「過去にあったもの」として現れるかもしれない。

一つの画像のなかで、三つの軸がズレる。

---

# 16｜ZURERU

ここでZURERUが再び重要になる。

**Appearance ≠ Reference ≠ Dependency.**

三つは一致する必要がない。

それぞれが別のrateで動く。

別のlagを持つ。

別の方向へ更新される。

つまり、history-bearingは一枚岩ではない。

historyそのものが、複数のrelationのなかでZUREうる。

いや。

「historyそのもの」と言った瞬間、また実体化している。

より慎重には、

**descriptions of history-bearing can diverge.**

---

# 17｜Tracehood revisited

ここまで来ると、Tracehoodについても問いを変えられる。

何かがTraceであるか。

ではなく、

> **Under which description does something work as a Trace?**

Phenomenological?

Semiotic?

Causal?

Relational?

複数か。

どれでもないか。

そして、

あるdescriptionではTraceとして働き、別のdescriptionでは働かない、ということもありうる。

もしそうなら、Tracehoodは単一属性ではない。

---

# 18｜実体化

ここで最初の問題へ戻る。

Traceを「もの」にしない。

Historyを「もの」にしない。

Relationも「もの」にしない。

そして、

System / Observerも、最終的な容器にしない。

何かがどこにあるのか、という問いを急がない。

代わりに、

**何が、どのconfigurationで、どのように区別されるのか**

を見る。

---

# 19｜RZはまだ呼ばない

ここまで来ると、R₀ / Z₀構文を呼びたくなる。

構文化。

切断。

現れ。

記号化。

残差。

しかし、まだ呼ばない。

RZを答えとして持ち込めば、現在の問題を過去の語彙に翻訳して終わる可能性がある。

まず、現在の問題を現在のまま、十分に露出させる。

そのあと、RZをTraceとして再び読む。

---

# 20｜Where Is History?

最初の問いは、

**Where is history?**

だった。

しかし、いまはこうなる。

**History may not need a where.**

問うべきなのは、historyが保存されている場所ではない。

later configurationが、どのような意味で、history-freeではないのか。

そして、

そのhistory-bearingを、われわれが、

Appearance.

Reference.

Dependency.

その他のどの構文で記述しているのか。

---

> **Do not ask where history is stored.**
> 
> **Ask how history enters the description.**

そして、

もしTraceという語が必要なら、

その仕事は、historyを保存することではない。

**異なるhistory-bearing descriptionsのあいだを、何かがどう横切るのかを区別すること**

なのかもしれない。

まだ、判決は出さない。
