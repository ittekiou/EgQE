# TUP-DN-18｜Fivefold Configuration

## Trace / Tracing / Updating / Practice / ZURERU

### 五項は、どう配置されるのか

> **Do not turn the five into a sequence.**  
> **Keep the tensions visible.**

[TUP-DN-17｜TraceとTracingは、何が違うのか｜Trace ≠ Tracing ── The Missing T](https://camp-us.net/articles/TUP-DN-17_Trace-Tracing_Missing-T.html)  

---

ここまでのTrialで、五つの語が残った。

**Trace**

**Tracing**

**Updating**

**Practice**

**ZURERU**

それぞれ、同じ仕事をしていない。

しかも、

どれか一つを起点にすると、残りが従属して見える。

だから、

まず順序を置かない。

---

# 1｜Five Terms

暫定的に、五つの仕事を分ける。

**Trace**

history-bearing configurationのなかで、

あるpositionを前景化する。

**Tracing**

prior / other configurationを、

follow / relate / traverseするprocessを前景化する。

**Updating**

configurationが、differenceをまたいでreconfigureされることを前景化する。

**Practice**

そのprocessにおいて、how-to-proceedが問題になることを前景化する。

**ZURERU**

どのconfigurationも、identity preservationへ閉じないことを露出する。

まだ定義ではない。

配置のための暫定記述である。

---

# 2｜No Center

五項の中心に、

Traceを置かない。

Tracingも置かない。

Updatingも置かない。

Practiceも置かない。

ZURERUも置かない。

なぜなら、中心を置くと、

他の四項がその派生に見えるからである。

五項は、一つの中心概念から枝分かれしたものではない。

少なくとも、現時点ではそう扱わない。

---

# 3｜Trace / Tracing

第一の緊張。

**Trace / Tracing**

Traceは、切断する。

Tracingは、辿る。

Traceは、あるpositionを止めて見る方向へ引っ張る。

Tracingは、そのpositionを別のconfigurationへ開く方向へ引っ張る。

しかし、

TraceはTracingなしに確定しにくい。

TracingはTrace-positionなしに、何を辿るか不明になる。

だから、二つは、

**≠**

でありながら、互いを呼び込む。

---

# 4｜Tracing / Updating

第二の緊張。

**Tracing / Updating**

Tracingは、何かを辿る。

Updatingは、何かをreconfigureする。

Tracingしても、Updatingしないことがある。

Updatingしても、Tracingしないことがある。

したがって、

**Tracing ≠ Updating.**

しかし、

TracingによってUpdatingが起きることもある。

Updatingによって、Tracingの仕方そのものが変わることもある。

ここには、

一方向ではないinteractionがある。

---

# 5｜Updating / Practice

第三の緊張。

**Updating / Practice**

Updatingは、configuration changeを扱う。

Practiceは、how-to-proceedを扱う。

何かが更新されても、それがPracticeとは限らない。

岩も変わる。

結晶も成長する。

しかしPracticeでは、単にconfigurationが変わるだけでなく、

**どう進むか**

が問題になる。

そして、

そのhow自体がUpdatingされうる。

---

# 6｜Practice / ZURERU

第四の緊張。

**Practice / ZURERU**

Practiceには、mannerがある。

しかし、

mannerが固定されれば、Practiceはtrackへ近づく。

決められた手順を、ただ再生するだけになる。

ZURERUは、その固定を壊す。

Encounterによって、mannerがズレる。

selectionが変わる。

how-to-proceedが更新される。

だから、

ZURERUはPracticeの失敗ではない。

むしろ、

PracticeがPracticeであり続ける条件の一部かもしれない。

まだ判決ではない。

---

# 7｜ZURERU / Trace

第五の緊張。

**ZURERU / Trace**

Traceを、同じものが残ることと考えるなら、

ZURERUは敵になる。

しかし、ここまでのTrialでは、

Traceにidentity preservationは要求できなかった。

すると、

ZURERUはTraceを破壊するとは限らない。

むしろ、

ZUREたあとでも、何かをhistory-bearingとして扱いたくなるから、

Trace問題が生じる。

つまり、

**Trace becomes interesting because things ZURE.**

完全に同じなら、copyで足りる。

完全に無関係なら、別Occurrenceで足りる。

Traceが必要になるのは、

その間である。

---

# 8｜A Pentagonal Configuration

すると、

五項は一列ではなく、五角形に近い。

```
          Trace
        /       \
   ZURERU       Tracing
      |           |
   Practice — Updating
```

ただし、これは因果図ではない。

矢印もない。

中心もない。

各辺は、

**tension / distinction / possible interaction**

を示すだけである。

---

# 9｜Why a Pentagon?

五角形なのは、五つあるから、というだけではない。

重要なのは、

隣り合う概念だけでなく、対角線にもrelationがあること。

Trace / Updating。

Trace / Practice。

Tracing / Practice。

Tracing / ZURERU。

Updating / ZURERU。

すべて、互いに干渉する。

だから、実際には単純な五角形でも足りない。

五項は、

**network**

として読む必要がある。

---

# 10｜Trace / Updating

TUPの中心緊張。

**Trace / Updating**

Traceは、history-bearingを前景化する。

Updatingは、reconfigurationを前景化する。

Traceは、何がlater configurationにmatterするか。

Updatingは、configurationがどう変わるか。

この二つを重ねると、古い問いが戻る。

> **How can something matter later without remaining the same?**

これが、

Trace Updatingの緊張である。

---

# 11｜Trace / Practice

TraceとPracticeも違う。

Traceは、history-bearing position。

Practiceは、how-to-proceed。

同じTrace候補でも、どう扱うかで、次のconfigurationが変わる。

スクリーンショット。

記憶。

文章。

犬の経験。

AIのcontext。

それらを、どう読むか。

どう使うか。

どう無視するか。

ここにPracticeが入る。

---

# 12｜Tracing / Practice

Tracingは、process。

Practiceは、manner。

だから、

同じものをTracingしても、Tracingの仕方が違う。

忠実に辿る。

飛ばす。

逆から辿る。

変奏する。

疑う。

比較する。

忘れる。

NAZORUは、ここへ近づく。

Tracingそのものより、

**mannered tracing**

へ。

---

# 13｜Tracing / ZURERU

Tracingしても、sameにはならない。

むしろ、Tracingするたびに、

対象も、Trace-positionも、meaningも、referenceも、

変わりうる。

だから、

**Tracing ≠ Reproduction.**

ZURERUは、Tracingのfailureではない。

Tracingがidentityを保存しないことを、

露出する。

---

# 14｜Updating / ZURERU

UpdatingとZURERUも、同じではない。

ZUREても、Updatingとは限らない。

ただdifferenceが生じただけかもしれない。

逆に、Updatingには、

configurationをreconfigurationとして読む構文がある。

したがって、

**ZURERU ≠ Updating.**

しかし、

Updatingがidentity preservationを要求しないなら、

ZURERUはUpdatingと共存する。

---

# 15｜NAZORU as a Crossing

ここで、NAZORUの位置が見える。

NAZORUは、五項のどれか一つではない。

Traceでもない。

Tracingだけでもない。

Updatingだけでもない。

Practiceだけでもない。

ZURERUだけでもない。

むしろ、

**Tracing / Updating / Practice / ZURERU**

の交差点に近い。

prior somethingを辿る。

しかしcopyしない。

そのmannerがある。

そしてZUREる。

さらに、

そのmanner自体もUpdatingされうる。

だから、

NAZORUは五項の内部に新しい箱として置くより、

**crossing practice**

として扱うほうがよいかもしれない。

---

# 16｜And Trace?

では、NAZORUとTraceはどうつながるのか。

何かをNAZORUするとき、Trace-positionが前提になるのか。

それとも、

NAZORUすることで、何かがTrace-positionを取るのか。

両方ありうる。

つまり、

TraceとNAZORUにも、起点を置けない。

ここでも、

**No First Station.**

---

# 17｜TUP as a Field

ここまで来ると、

TUPをsequenceではなく、

**field**

として読む可能性が強くなる。

Trace。

Tracing。

Updating。

Practice。

ZURERU。

それぞれの緊張が、configurationごとに違う。

ある場面ではTraceが前景化する。

ある場面ではTracing。

ある場面ではUpdating。

ある場面ではPractice。

ある場面ではZURERUだけで十分。

つまり、

TUPは、すべてを毎回使う理論ではない。

**どのdifferenceを、どの語で切るとdiscriminationが増えるか**

を見るfieldである。

---

# 18｜No Mandatory Route

だから、

Traceから始める必要はない。

Tracingから始めてもよい。

Updatingから始めてもよい。

Practiceからでもよい。

ZURERUからでもよい。

そして、

必要がなければ、Traceを使わなくてもよい。

これが、

Trace on Trialを通ったあとのTUPに必要な自由度かもしれない。

---

# 19｜TUP and NZR

TUPとNZRの関係も、少し見える。

TUPは、

history-bearing / reconfiguration / manner

を監査するfield。

NZRは、

NAZORUというpracticeを通して、

Tracing / Updating / ZURERUの交差を観察する。

つまり、

NZRはTUPの下位理論ではない。

TUPもNZRの上位理論ではない。

**異なる入口から同じfieldへ入る。**

そう考えたほうが、閉じにくい。

---

# 20｜The Strange Position of ZURERU

五項のなかで、ZURERUだけが少し異質である。

Trace。

Tracing。

Updating。

Practice。

これらは、何らかの記述構文を作る。

ZURERUは、

それらの構文が、identityへ閉じようとしたとき、

その閉包を崩す。

だから、ZURERUは五項の一項でありながら、

同時に、

**五項全体への監査圧**

でもある。

---

# 21｜The Strange Position of Trace

Traceも異質である。

Tracing。

Updating。

Practice。

ZURERU。

これらはprocess / manner / difference側へ寄る。

Traceだけは、

position / cut側へ寄る。

だから、

TraceはTUPのなかで、固定化の危険を最も強く持つ。

しかし、

その危険があるからこそ、一時的な切断点を作れる。

つまり、

Traceは、

**危険だから不要**

なのではない。

**危険だから監査しながら使う**

語なのかもしれない。

---

# 22｜The Strange Position of Practice

Practiceも異質である。

Trace。

Tracing。

Updating。

ZURERU。

これらだけなら、descriptionで済むかもしれない。

Practiceを入れると、

**how-to-proceed**

が問題になる。

つまり、

記述から作法へ踏み込む。

ここで初めて、

理論自身のmannerまで問われる。

どうTraceするか。

どうTracingするか。

どうUpdatingするか。

どうZUREを扱うか。

Practiceは、理論そのものにも返ってくる。

---

# 23｜Fivefold Audit

暫定的に置く。

|Term|Foregrounds|Main Risk|
|---|---|---|
|Trace|position / history-bearing|substantialization|
|Tracing|following / traversing|hidden prior connection|
|Updating|reconfiguration|collapse into change|
|Practice|manner / how-to-proceed|agency inflation|
|ZURERU|non-identity / deviation|collapse into mere difference|

五つとも、Gainがある。

五つとも、Costがある。

だから、

どれかを基礎概念として固定しない。

---

# 24｜No Ontological Winner

現時点では、

五項のなかに、存在論的な勝者はいない。

Traceが基礎ではない。

ZURERUが基礎とも言わない。

Practiceが生命の本質とも言わない。

Updatingが宇宙の基本運動とも言わない。

Tracingがすべてを説明するとも言わない。

必要なのは、

**どのconfigurationで、どの語がdiscriminationを増やすか**

を見ること。

---

# 25｜From Theory to Manner

ここで、TUPが少し違って見える。

TUPは、

世界がどうできているかを、一発で説明する理論ではない。

むしろ、

Traceを実体化しない。

Tracingをconnectionへ閉じない。

UpdatingをChangeへ溶かさない。

PracticeをAgencyへ閉じない。

ZURERUをNoiseへ落とさない。

そのための、

**theoretical manner**

なのかもしれない。

---

暫定配置。

> **Trace cuts.**
> 
> **Tracing follows.**
> 
> **Updating reconfigures.**
> 
> **Practice asks how.**
> 
> **ZURERU keeps the configuration open.**

五つは、

一つのsequenceではない。

一つの階層でもない。

一つの因果鎖でもない。

**Field of tensions.**

そこに、

TUP / NZR / RZ / QASが、それぞれ別の角度から入ってくる。
