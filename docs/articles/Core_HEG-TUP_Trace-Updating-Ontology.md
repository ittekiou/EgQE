# HEG第四期としてのTrace Updating Ontology（TUP）

[EgQE｜HEG-Genesis｜構文生成進化と深化の地層史 ── From Cosmos to Life](https://camp-us.net/Core_HEG-Genesis_From-Cosmos-to-Life.html)  

---

HEG（Hybrid Echo Genesis）は、段階的に生成構文を露出させてきた。

**HEG第一期**は、**relation cosmology** であった。

**関係**が存在に先立つことを示し、**生成**を宇宙論として記述した。

**HEG第二期**は、**lag / persistence cosmology** であった。

生成は**lagとして持続**し、その持続様式の差として時間・物質・生命が現れることを記述した。

**HEG第三期**は、**lag editing cosmology** であった。

生成を**編集（Editing）** の観点から捉え直し、生命・宇宙・AIを編集過程として記述する視点が導入された。

そして現在、新たな位相が現れつつある。

それが **Trace Updating Ontology（TUP）** である。

```
HEG第一期
relation cosmology

↓

HEG第二期
lag / persistence cosmology

↓

HEG第三期
lag editing cosmology

↓

HEG第四期
Trace Updating Ontology（TUP）
```

---

## Updatingの内部構造

これまでHEGでは、

> **存在とは更新である。**

という命題を掲げてきた。

しかし、Updatingそのものは、なお抽象的な概念として残されていた。

TUPは、その内部構造を最小構文として記述する。

```text
Trace₀
→ Signal₀
→ Updating Practice₀
→ Trace₁
→ …
```

更新の向きは一方向であり、非可逆である。

時間とは、この更新方向（→）の経験である。

存在とは、この更新の局所的安定状態である。

---

## HEG第四期

したがって、TUPはHEGとは別の理論ではない。

HEG第一期から第三期までに蓄積されたTraceを、新たなSignalによって再編集した結果として現れた位相である。

HEG第四期とは、**Trace Updating Ontology** の展開である。

Updatingは、もはやブラックボックスではない。

**Trace・Signal・Updating Practice**という最小構文として記述される。

---

```
HEG第一期
関係（Relation）
「世界はいかに始まるのか」

        ↓

HEG第二期
持続（Persistence / Lag）
「世界はいかに続くのか」

        ↓

HEG第三期
編集（Editing）
「世界はいかに更新されるのか」

        ↓

HEG第四期
Trace Updating Practice（TUP）
「更新はいかに実装されるのか」
```

- **第一期**　生成条件（Relation）
- **第二期**　持続条件（Persistence）
- **第三期**　更新条件（Editing）
- **第四期**　更新機構（TUP）

> - Relation は Persistence の中に生きている。
> - Persistence は Editing の中に生きている。
> - Editing は TUP の中に生きている。

_HEGの問いは、「更新そのものの実装」へ到達した_

---

### HEG第一期　関係論（Relation）

世界はどのように立ち上がるのか。

生成を関係から読む。

ここでは、まだTraceは「生成されたもの」の一部として位置づけられていた。

---

### HEG第二期　持続論（Persistence）

世界はどのように続くのか。

lagとPersistenceによって、時間・物質・生命を記述する。

Traceは「持続の痕跡」として重要性を増す。

---

### HEG第三期　編集論（Editing）

転回点。

世界は単に持続するだけではない。**編集される。**

Editが入ったことで、

- 摂取
- 編集
- 排泄

という生命の更新様式が見え始めた。

そして、宇宙・生命・AI・制度を**編集**という共通構文で読めるようになった。

---

### HEG第四期　Trace Updating Ontology（TUP）

ここで初めて、Updatingがブラックボックスではなくなる。

Traceは保存物ではなく、Signalによって読み直され、Updating Practiceによって編集され、新たなTraceを生む。

```
Trace₀
→ Signal₀
→ Updating Practice₀
→ Trace₁
→ …
```

この最小構文が見えた。

---

> Editは生命の内部操作。Updatingは存在全体の生成構文。

> **Updatingは、もはやブラックボックスではない。**

_存在とは、更新の局所的安定状態である。_
