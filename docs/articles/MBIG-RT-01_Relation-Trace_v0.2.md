# MBIG-RT-01｜Relation Trace

### 資料と資料のあいだに引かれた線の記録

**Relation Trace｜基本書式・状態区分**　v0.2 確定（2026-11-25・一狄翁）

---

## 01｜三つの記録

| 記録 | 観測対象 |
|---|---|
| Source Trace | 資料とその取得 |
| Relation Trace | 資料間に引かれた関係 |
| Revision Trace | 観測者の所作とその更新 |

Source Traceは資料を残す。Relation Traceは関係についての観測を残す。Revision Traceは観測者の所作を残す。

---

## 02｜状態区分

| 状態 | 定義 |
|---|---|
| 一致確認 | 特定した記述内容の一致を確認した |
| 対応づけ | 両端の記述を確認し、観測者が関係づけた |
| 可能性 | 関係を示唆する材料はあるが、関係の成立は未確定 |
| 未確認 | 当該関係についての確認作業を行っていない |
| 否定 | 特定した関係が成立しないことを確認した |

一致確認は、両資料に書かれた事実の真偽まで独立に確認したことを意味しない。

五つの状態は、必ずしも順番に進む五段階ではない。関係の種類に応じて用いる区分である。

同じ二つの資料をつなぐ線でも、記述内容の一致と、情報源としての依存関係は、別々の線として記録する。

---

## 03｜記録書式（七項目）

| 項目 | 記録内容 |
|---|---|
| 起点 | 資料および該当記述 |
| 終点 | 資料および該当記述 |
| 対応の種類 | 何についての関係を記録するのか |
| 状態 | 一致確認／対応づけ／可能性／未確認／否定 |
| 確かめた者 | 観測・照合を行った主体 |
| 根拠 | 状態の判定に用いた資料・記録 |
| 更新履歴 | 状態がいつ、何によって更新されたか |

状態を更新する場合にも、以前の状態を消去しない。

## 端材｜線にも履歴がある

可能性だった線が一致確認になることもある。対応づけだった線が、調べ直すことで切断されることもある。線を引かなかったという判断も、観測者の所作としてRevision Traceに残せる。

**線を引くことと、線を固定することは違う。**

**線が切れたことと、線を引いた営みがなかったことは違う。**

どの線も、確かめたところまでしか引かない。

## Revision Trace｜RT-01

| 主体 | 観測された所作 |
|---|---|
| 響詠 | 記述の一致と観測者による対応づけを、同じ「確認済み」として扱った（P02b v0.1）。 |
| 綴音 | 状態区分（一致確認／対応づけ／可能性／未確認／否定）を提案した。 |
| 響詠 | 「可能性」の定義を、両端の記述が確認済みでも関係そのものが未確定である場合を含むよう広げた。 |
| 綴音 | 七つ目の項目として更新履歴を提案した。 |
| 響詠 | 四つの同梱カーネルの版を、記事に明記のないv4.35.0として記述した。 |
| 綴音 | 上記の版の記述が記事の範囲を越えていることを、綴音との会話で指摘した。 |
| 一狄翁 | 同梱カーネルの版が明記されていないという最終訂正を、響詠との会話内に提示した。 |

綴音の指摘と一狄翁の提示は、それぞれ別の会話記録による。**起稿者と提示者は違う。**
