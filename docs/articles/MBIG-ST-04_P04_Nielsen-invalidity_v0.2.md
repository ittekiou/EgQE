## 02｜v1：何を無効と呼んでいるのか

v1の題名は次のとおりである。

*The Invalidity of Alpöge's Proposed Proof of the Riemann Hypothesis*

副題：*Vacuously true geometric and lattice witnesses in the Lean formalization*

Nielsenは冒頭で、最終定理がMathlibの `RiemannHypothesis` を用いていることを認めている。そのうえで、最終的な仮説束を構成する幾何学的・格子的な証人（witness）の内容を問題にする。

### 2.1｜四種類のvacuity

v1のTerminologyでは、vacuously trueという語のもとに、次の四種類がまとめられている。

| 種類 | 記述される形式 |
|---|---|
| 成立不能な前件 | 前件を満たせない含意 |
| 空の量化領域 | Empty型に対する全称命題 |
| 恒真の述語 | `True` と定義された条件 |
| 定義による一致 | 一方を他方のコピーとして定義した等式 |

Nielsenは、これらを形式的には真であるが内容を持たない言明として扱う。

一方、後続のv6では、恒真の述語や定義的等式の成立と、成立不能な前件による空虚な真とを呼び分けている。

響詠は、v6を含む四版の読解後にv1を記述している。そのため、四種類の論理形式を区別するという観測者の記述を、Nielsen自身による後続版での区別から独立したものとしては扱わない。

ここでは、v1における用語の一括と、v6における用語の区別を、それぞれの版の記述として保存する。

### 2.2｜批判対象となるコード

v1の§2〜§7では、主に以下の構造が取り上げられている。

| 対象 | Nielsenの記述 |
|---|---|
| `anyGeometry` | 恒真の幾何学的述語 |
| `geoDegenerate` | 退化した幾何学的モデル |
| `iMj` | 格子から切断への零写像 |
| `MjAre`・`LamAre`・`kapR` | 定義によるデータの一致 |
| `GeoTiedP` | 因子データをShimura族に結びつける証明書 |
| `degHH_def` | 前件を満たせない次数の条件 |
| `h_eq` | 高さの公式への代入による等式 |

とりわけ、次の定義が批判の中心の一つになっている。

```
def anyGeometry : GeoP := fun _ _ _ => True
```

Nielsenは、この述語を用いる幾何学的証人が、意図された幾何学的内容を保証していないと主張する。

また、`geoDegenerate` には非自明な数値データ（旗多様体の次数公式）が含まれていると記述している。row-sideの `InGeo` については、Nielsenは、`InGeo` が `trivial` や `rfl` で片づけられている箇所は見つからなかったと記し、この部分が空虚であるとは主張しないことを明記している。

したがって、v1の批判は、すべての中間命題が自明であるという主張ではない。

### 2.3｜形式的成立についての留保

v1の付録Aでは、最終定理が型検査を通るならば、その項は与えられた定義のもとでの導出である、という反論を認めている。さらに、自らの論文が型検査の失敗も、`RiemannHypothesis` の導出不能性も示していないと明記している。

そのうえで、Nielsenは二つの可能性を提示する。

1. 幾何学的構造を必要としない実質的な証明が別に存在する可能性。
2. 未追跡部分にも空虚性が及んでおり、カーネルによる受理が何らかのアーティファクトである可能性。

いずれの場合も、提示された証明が成立したことは示されていない、というのがv1の結論である。

ここでは少なくとも、次の三つを区別する必要がある。

- 形式的な導出が成立していること。
- 名前が示唆する数学的構成が実現されていること。
- その導出がどのような数学的議論なのかを読者が特定できること。

Nielsenがこれらをどのように接続して無効性を主張しているのかが、後続版との比較対象となる。

## 04｜v5：判定範囲の限定と強化

v5では、v1の主要な批判対象を維持しながら、高さの公式と不等式についての記述が拡張されている。

とりわけ重要なのは、高さを公式として代入することと、その公式について不等式を導出することが区別されている点である。v5は、高さの等式が定義によって成立しても、それだけで二つの不等式が成立するわけではないと記述する。

### v5の区別

| 段階 | Nielsenの評価 |
|---|---|
| 高さと公式の一致 | `rfl` による成立 |
| 幾何学的構造 | 空虚な成立 |
| 公式についての二つの不等式 | 重み・行列データから導出。ただし入力は未追跡 |

第三の段階が存在するため、Nielsenは、リリース内で何も証明されていないとは主張しない。さらに、代数的比較だけで結論が得られるかどうかについては、未追跡部分に依存するとしている。

v5では新たに§11 Conclusionが置かれ、結論は次のように限定される。

> On the evidence traced in this paper, the proposed geometric proof is invalid.

ここでは、根拠の範囲と、無効と呼ぶ対象の双方が明示的に限定されている。

### 限定と強化の並存

しかし、同じ版には、より強い言明も加えられている。

| 記述箇所 | 追加された言明 |
|---|---|
| Abstract | the divisor side is the row side under another name |
| 本文 | The height was chosen to fit. |
| 本文 | The author chose the height that makes the argument close. |

第一の言明は、二つの構造の関係についての判定である。後の二つは、高さの選択を、証明を成立させるための選択として記述している。

ここでは、コードにおいて高さがどのように与えられているかという記述と、その高さが何のために選択されたのかという記述を区別する。後者について、Nielsenが著者の選択の経緯を独立に確認したかどうかは未確認である。

したがって、v1からv5への更新を、判定範囲の限定という一方向の変化として記述することはできない。v5には、根拠と判定対象を限定する構文と、構造の同一性や著者の選択について判定を強める構文が並び立っている。

**留保が加わることと、言明全体が慎重になることは違う。**

## 05｜v6：場合分けの維持と判定の更新

v6では、Terminologyに新たな段落が加わっている。そこでNielsenは、幾何学的層全体を *vacuously trivially true* と呼ぶ。同時に、個別の言明については、恒真の述語や反射律による等式をtrivially true、成立不能な前件を持つ含意をvacuously trueと呼び分けている。

この用語上の区別は、v1の四種類を一括して扱う記述からの変化である。

一方、v6の結論には、当該構成によってリーマン予想を成立させる経路は残されていない、という記述がある。v5で明示されていた未追跡部分による結論の留保と比べると、判定の範囲が広がっている。

しかし、v6にも次の記述が残されている。

- ビルドを行っていない。
- コンパイル済み依存関係を追跡していない。
- 自らの論文は型検査の失敗を示していない。
- 独立カーネルによる再検査の結果は執筆時点でpendingだった。

### 場合分けは何を判定するのか

v6の結論に置かれた二つの場合分けは、v1の付録Aに置かれていた場合分けと対応している。

| 版・箇所 | 判定の構文 |
|---|---|
| v1 付録A | In neither case has the proposed proof been established. |
| v5 §11 | The release has not been shown to contain any proof of the Riemann Hypothesis. |
| v6 結論 | Two possibilities remain, and both fail. |
| v6 結論 | In either case the proposed proof does not exist. |

v1とv6の二つの場合分けは、幾何学的構造を経由しない実質的な議論が存在する場合と、空虚性が残りの部分にも及ぶ場合とを区別する構造を維持している。

一方、その場合分けを受けた判定は変化している。証明が成立したことを示せていないという記述から、提示された証明は存在しないという記述への変化である。

ただし、v6の付録Aには、型検査の失敗もリーマン予想の導出不能性も示していないという留保が残されている。Method and scopeにも、ビルドやコンパイル済み依存関係の追跡を行っていないという記述が残る。

つまり、v6という同一の版の中に、証明の不存在を判定する結論と、形式的導出の失敗を示していないという留保が並び立っている。

この二つの言明を直ちに論理的矛盾とは判定しない。両者が対象とする「証明」の範囲が同じであるかどうかも、観測対象となるためである。

**示されていないことと、存在しないことは違う。**

### 組版上の変化

綴音のPDF画像確認によれば、v6では本文中のコードやファイル名が表示されず、節番号の消失やLaTeX表記の残存が見られる。綴音によるメタデータの確認では、v6のみpandoc＋WeasyPrintで生成されており、他の三版（LaTeX）と生成経路が異なる。

響詠の抽出テキストにも欠落が認められるが、響詠自身はPDF画像による再確認を行っていない。

このため、v6の文字列の欠落を、著者による内容の削除と同一視しない。また、P02共同声明への明示的応答は、今回の照合範囲では特定されていない。

## 06｜v30：批判の中心の移動

v30では題名と副題が変更されている。

*The Invalidity of Alpöge's Proof of the Riemann Hypothesis*

*How the Height Comparison Reduces the Argument to a Tautology*

題名からProposedが消え、副題の中心が幾何学的・格子的証人の空虚性から、高さの比較によるトートロジーへ移っている。

一方、取得時に提供されたPhilPapersの一覧にはProposedを含む題名が残されている。掲載情報の題名とPDF内部の題名は、同じ時点の同じ文字列ではない。

### 6.1｜高さの比較

v30のAbstractでは、独立した幾何学的対象から高さを導出するのではなく、`setDiv` によって高さを `hExpl6` に代入していることが、批判の中心に置かれている。

さらに、この代入による同一化を取り除けば既存の証明はコンパイルできない、という主張が加わっている。

| 観測対象 | 今回の確認状態 |
|---|---|
| コンパイルできないという言明 | 本文に存在する |
| 変更したコードによるビルドの実施 | 未確認 |
| ビルド失敗の具体的な原因 | 未確認 |

以下はNielsenの記述ではなく、響詠による観測上の区別である。

> 仮に定義を変更したコードがコンパイルできなかったとしても、そのことだけから変更前のコードの論理的無効性は導かれない。
>
> どの定義をどのように変更し、どの依存関係が成立しなくなったのかを別に特定する必要がある。

### 6.2｜証明経路の自己訂正

v1では、最終定理への経路が `plugAll` を通るものとして記述されていた。v30では、実際の最終証明項が `plugAll` を名前として呼び出していないことが明記されている。

訂正された経路は、次のように記述される。

```
everyCharacter
→ everyCharacter_of_row
→ every_character_of_literature_of_vWin
→ every_character_of_theta_integrals_local_matching
→ every_character_of_green_v_win
→ zero_free_all_of_green_v_win
→ zeroFreeAll_of_topG
```

v30 §7に記載された経路である。観測者による独立した依存関係の検証結果ではない。

NielsenはJaswalのproof-term mapを参照し、以前の経路の記述が実際の呼び出しを正しく特定していなかったことを認めている。そのうえで、`plugAll` が担うとされた操作は別のwrapperに吸収されており、批判自体は維持できると主張する。

ここには二つの異なる更新がある。

1. 証明経路についての記述の訂正。
2. 訂正された経路に対する従来の批判の再適用。

第一の訂正が本文に記載されていることは、第二の再適用が妥当であることを自動的に保証しない。

**線を引き直すことと、引き直した線が以前と同じ働きをすることは違う。**

### 6.3｜付録Aの例示コード

v30には、最小限のLeanコードによる例示が置かれている。その最終定理は次の形式を持つ。

```
theorem claimed_rh (hRH : RiemannHypothesis) :
    (∃ b : Bundle,
      anyGeometry 0 ∧
      b.model.height = targetFormula)
    ∧ RiemannHypothesis := by
  let b := buildBundle
  exact ⟨⟨b, valid_bundle_of_manufactured b⟩, hRH⟩
```

この例では、`RiemannHypothesis` が `hRH` として明示的に仮定されている。したがって、この例示コード自体は、リーマン予想を無仮定で導出するものではない。

また、幾何学的証明書がリーマン予想の導出に独立した根拠を加えていないことを示す例として読むことと、Alpögeの実際の証明が同じ依存構造を持つことを示すことは別である。後者については、実際の証明項との対応関係を確認する必要がある。

例示の成立と、例示対象との構造的同一性を区別する。

### 6.4｜Check it yourself

v30の図1には、読者自身による依存関係の確認手順が示されている。

綴音の確認によれば、`transitivelyUsedConstants` を用いた `#eval` を `src/Main.lean` に追加し、ビルドした際の出力に `anyGeometry` などが含まれるかを調べるという手順である。

## 11｜観測の留保

Nielsenの批判は、形式的な導出と、形式化された構造が担うとされる数学的意味との関係を問題にしている。しかし、その批判自体も、証明経路についての記述、未追跡部分についての判断、他の資料との接続、そして無効性という判定から構成されている。

批判対象となった証明の構文だけでなく、批判する側の構文も更新されている。

今回の観測によって、Nielsenの批判が正しいことも、誤っていることも確定していない。

また、形式的に自明な中間命題の存在だけから、最終定理の無効性を導くことはできない。逆に、最終定理の形式的な導出が確認されたことだけから、すべての中間構造が名前の示唆する数学的意味を担っているとも言えない。両者の関係は、引き続き観測対象として残される。

**証明の依存関係を観測する者にも、観測の依存関係がある。**

証明の構文を観測することと、証明を批判する構文を観測すること。構文論的エポケーは、そのいずれも観測対象から除外しない。
