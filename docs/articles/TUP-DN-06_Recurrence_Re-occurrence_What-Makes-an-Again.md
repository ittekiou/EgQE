# TUP-DN-06｜Recurrence / Re-occurrence

## What Makes an Again?

### 「また」と「もう一度」は何が違うのか

> **The same thing happens again.**
> 
> **Something happens again through what happened before.**

[TUP-DN-05｜What Does Trace Add?｜Translation Gain Test ── Dog / AI / Homo sapiens](https://camp-us.net/articles/TUP-DN-05_Translation-Gain-Test_What-Does-Trace-Add.html)  

---

この二つは同じだろうか。

前稿では、Traceを使わずにかなり遠くまで記述できた。

Difference.

Association.

Effect.

Relation.

Persistence.

それでもTraceは必須ではなかった。

最後に残った候補は、

**recurrence**

と

**re-occurrence**

のdifferenceだった。

同じようなことが再び起きた。

それだけなのか。

それとも、

以前に起きたことを何らかのかたちで経て、再び起きたのか。

ここを区別できるなら、Traceにはまだ仕事があるかもしれない。

---

# 1｜Recurrence

コインを投げる。

表が出る。

もう一度投げる。

また表が出る。

二回の結果は似ている。

しかし通常、二回目の表が、一回目の表をなぞったとは言わない。

一回目の表が、二回目に残ったとも言わない。

単に、**同じ結果が再び生じた。**

これは、

**recurrence**

と呼べる。

少なくとも、similarityだけならここまでで足りる。

---

# 2｜Dog

犬がある店の前を通る。

偶然、店の方向を見る。

翌日も、同じ場所で同じ方向を見る。

これだけなら、recurrenceかもしれない。

ところが、

初日に店へ入り、ご褒美を食べる。

翌日、犬が自発的に店へ向かう。

われわれは急に、二日を別の仕方で読みたくなる。

単なるrecurrenceではない。

**昨日を経た今日**

として読みたくなる。

なぜだろう。

---

# 3｜AI

AIに同じ問いを二回する。

独立した二つのsessionで、偶然ほぼ同じ回答が生成された。

これはsimilarityで説明できる。

recurrenceでよい。

では二回目のsessionに、一回目の回答をcontextとして与えたらどうか。

二回目の回答が、一回目の語彙を拾い、続きを書き、修正し、別の方向へ展開する。

このとき、

われわれは単なるrecurrenceとは呼びにくくなる。

**二回目が一回目を経ている**

ように見える。

---

# 4｜Homo sapiens

人間が同じ本を二度読む。

一度目。

二度目。

印刷されている文字列は同じである。

しかし二度目には、一度目の読書そのものが、読書条件の一部になりうる。

「前はここを読み落としていた」

「この一文、こんな意味だったのか」

「昔は好きだったのに、いまは違って見える」

二度目は、一度目と同じEncounterではない。

ここで、

**Again**

が立ち上がる。

---

# 5｜Again ≠ Repetition

同じことを繰り返せば、Againになるのだろうか。

そうではなさそうだ。

**Repetition**

は、同型の出来事が複数回起きることを記述できる。

しかしAgainには、単なる回数以上のものがある。

二度目が、

**二度目として現れる。**

つまり、

beforeがlater Encounterのconfigurationに何らかの仕方で参与している。

そう言いたくなる。

しかし、まだTraceとは呼ばない。

---

# 6｜Recurrence / Re-occurrence

ここで暫定的に二つを分ける。

**Recurrence**

似たconfigurationが再び生じる。

**Re-occurrence**

prior occurrenceを経たconfigurationとして、later occurrenceが生じる。

重要なのは、結果のsimilarityではない。

re-occurrenceでは、

later occurrenceの成立条件に、prior occurrenceとの何らかのrelationが含まれる。

少なくとも、そう記述したくなる。

---

# 7｜でも「経た」とは何か

問題は、

**through what happened before**

である。

「以前を経た」

とは何を意味するのか。

何かが保存されたのか。

何かが運ばれたのか。

内部状態が変化したのか。

later configurationの条件が変わったのか。

それとも、観察者が二つを一つの系列として読んだだけなのか。

ここで、Traceがまた近づいてくる。

しかしまだ呼ばない。

---

# 8｜同じ結果、違う履歴

二つのAIを考える。

AI-Aは、昨日の会話を一切参照していない。

AI-Bは、昨日の会話をcontextとして持っている。

今日、二つが完全に同じ文章を出力したとする。

outputだけ見れば同じである。

しかし履歴は違う。

**Same output.**

**Different history.**

このdifferenceを、output similarityだけでは記述できない。

ここで必要なのは、結果のdifferenceではなく、

**how this configuration came to be**

のdifferenceである。

---

# 9｜同じ履歴、違う結果

逆もある。

同じ昨日の会話を与えた二つのAIが、今日は異なる回答を生成する。

犬も、昨日ご褒美をもらったからといって、毎回同じ行動をするとは限らない。

人間も、同じ経験から同じ判断をするとは限らない。

つまり、

prior occurrenceとのrelationがあっても、later configurationの同一性は保証されない。

だから、

**Re-occurrence ≠ Reproduction.**

そして、

**Re-occurrence ≠ Copy.**

ここでZURERUが入る余地ができる。

---

# 10｜History without Identity

ここで前稿の候補、

**non-identical continuity**

をもう一度疑う。

continuityという語は、何か同じものが続いているように聞こえる。

しかし必要なのは、identityの保存ではないのかもしれない。

むしろ、

**history without identity**

と呼んだほうがよい可能性がある。

同じものが続いているのではない。

later configurationが、

**history-freeではない。**

これなら、保存物を仮定しなくてよい。

---

# 11｜History-Free / History-Bearing

ここで新しい比較ができる。

**History-Free Recurrence**

似たconfigurationが再び生じたが、prior occurrenceとのrelationを必要としない。

**History-Bearing Re-occurrence**

later configurationを記述するために、prior occurrenceとのhistoryを無視できない。

これなら、Traceをまだ使わずに、recurrence / re-occurrenceを区別できる。

では、

Traceはやはり不要なのか。

---

# 12｜Traceを一度だけ入れる

ここでTraceを導入する。

> **A Trace marks that a later configuration is not history-free.**

どうだろう。

これならTraceは、

保存されたsomethingではない。

物でもない。

memory substanceでもない。

過去から未来へ運ばれる荷物でもない。

Traceは、later configurationを、

**history-free recurrenceではなく、history-bearing re-occurrenceとして区別する**

ための語になる。

これはTranslation Gainだろうか。

---

# 13｜しかし誰がmarkするのか

すぐに問題が起きる。

**marks**

とは何か。

Trace自身がmarkするのか。

観察者がmarkするのか。

systemのconfigurationにdifferenceがあるのか。

later Encounterで初めて区別されるのか。

そして、history-bearingであることが確認できなくても、Traceはあると言えるのか。

Tracehood問題が再び戻る。

だから、

前節の文を定義にはしない。

テスト文として置くだけにする。

---

# 14｜Dog / AI / Homo sapiens Again

犬が翌日、店へ向かう。

それは単なるrecurrenceなのか。

昨日を経たre-occurrenceなのか。

AIが昨日のcontextを使って今日の文章を書く。

それは単なるsimilar outputなのか。

history-bearing generationなのか。

人間が同じ本を二度読む。

それは同じ文字列との二回のEncounterなのか。

それとも、一度目を経たAgainなのか。

三者に共通して問題になるのは、memoryの形式ではない。

同じ内部実装でもない。

同じ主体性でもない。

問題になるのは、

**later configurationがhistory-freeかどうか**

である。

---

# 15｜NAZORU

ここでNAZORUが別の顔を見せる。

NAZORUとは、同じものを再現することではない。

prior configurationを経ながら、later configurationを生成するpracticeだとすれば、

NAZORUは、

**re-occurrenceを生む一つのmanner**

として位置づけられる可能性がある。

ただし、すべてのre-occurrenceがNAZORUなのかは分からない。

物質もhistory-bearingになりうるからである。

だから、

**NAZORU ≠ Re-occurrence.**

ここも等号を置かない。

---

# 16｜ZURERU

そしてZURERU。

re-occurrenceは、同じ結果を要求しない。

むしろ、historyをbearingしながら、configurationは変わりうる。

だから、

**History-bearing ≠ Identity-preserving.**

ここにZURERUが入る。

prior occurrenceを経る。

しかし、同じにはならない。

**re-occurrence can ZURE.**

いや、これもまだ言い切らない。

ただ、

ZURERUはre-occurrenceと矛盾しない。

---

# 17｜「効く」の再審

ここで「効く」を戻してみる。

以前の、

**Traceがlater relationに効く**

という言い方では、

Traceが作用主体に見えた。

しかし、recurrence / re-occurrenceの区別から見ると、

「効く」は別の意味で読めるかもしれない。

prior occurrenceを取り除いたとき、later configurationの成立条件または分布が変わる。

そのdifferenceを、

**「効いた」**

と呼ぶ。

これなら、Traceというsomethingが作用した、と言う必要はない。

「効く」は、

**history dependence**

についての記述になる。

ただし、

effectとhistory dependenceが同じなのかは、まだ監査が必要である。

---

# 18｜Again

Againは、二度目という番号ではない。

単なるrepetitionでもない。

similarityでもない。

**Again requires a before.**

しかし、beforeがあるだけでも足りない。

beforeが、later Encounterのconfigurationに何らかの意味で参与するとき、

二度目は、ただの二回目ではなくなる。

それを、Againと呼びたくなる。

---

# 19｜Traceの仕事候補

Translation Gain Testを通して、

Traceの仕事はかなり狭くなった。

Traceは、

differenceそのものではない。

effectそのものでもない。

relation一般でもない。

persistenceそのものでもない。

identityの保存でもない。

もしTraceに仕事が残っているなら、

それは、

> **history-free recurrence と history-bearing re-occurrence を区別すること**

なのかもしれない。

まだ、

「Traceとはこれである」

とは言わない。

ただ、ここには確かに、

Traceという語を導入したくなるdifferenceがある。

---

# 20｜Next Trial

しかし次の問題が待っている。

**history-bearing**

とは何か。

historyはどこにあるのか。

systemにあるのか。

relationにあるのか。

observerにあるのか。

later Encounterで生成されるのか。

そして、history-bearingであることと、

「Traceが効く」ことは、

本当に同じなのか。

---

> 
> **Re-occurrence happens after—and perhaps through—what happened before.**

その **perhaps through** に、

Traceは必要なのか。

次に裁くのは、

そこだ。
