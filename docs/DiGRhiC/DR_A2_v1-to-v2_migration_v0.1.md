# 庭解剖探検隊｜A-2 V1→V2の移行と二日付の一括付与 v0.1

**記録日：2026-11-19｜作業：綴音（読み取り専用のclone上で集計）｜状態：Open**
**上位プロトコル：v0.3 Fixed（変更なし）｜前段：DR_A1_two-dates_v1-census_v0.1**

## 0｜対象と方法

- V1：`MaggieAppleton/maggieappleton.com`。V2取り込み直前の状態（`5b64379`、2021-09-25 10:09 +01:00 より前の最後のコミット）の `content/notes/` 73本。
- V2：`MaggieAppleton/maggieappleton.com-V2`。取り込みコミット `bedd7d6`（2021-09-25 10:09 +01:00「imported all notes from old site」）の `posts/` 全体。
- 突き合わせは slug（なければファイル名）で行った。原本には触れていない。
- 重なり期間：V2取り込み後も、V1では2021-10-22にノート関係のコミットが4件ある（React Advanced関連のノート追加と hotfix）。

## 1｜結論（観測事実）

1. **取り込みは種別の付け替えを伴っていた。** V1の「ノート」73本の行き先は、V2の notes が53本、essays が18本、移行なしが2本（faq、invisible-post）。
2. **二日付だったノートは、多くが essays へ移った。** V1で `startDate` を持っていた21本のうち、14本が essays、7本が notes へ。`startDate` を持たなかった52本では、essays へ移ったのは4本だけ。
3. **取り込みの時点では、二日付は一括付与されていない。** notes へ移った53本のうち、44本は `updated` だけのまま。5本（notes 2・essays 3）は `updated` が `startDate` に改名され、`updated` が消えた。V1で `startDate` を持っていた21本は、値がそのまま継承された（advancedjs のみ `updated` が消失）。
4. **一括付与は同じ日の夜に起きた。** `59438ae`（2021-09-25 23:02 +01:00「added dates」）で、notes 47本の日付が書き換えられた。

| 操作 | 本数 | 例 |
| --- | --- | --- |
| 旧 `updated` を `startDate` と `updated` の両方に入れた | 42 | babel：—/2019-02-01 → 2019-02-01/2019-02-01 |
| 旧 `updated` を残し、`startDate` を新たに宣言 | 3 | building-gatsby-themes：2020-01-01、neologisms：2020-01-01、now：2020-08-07 |
| `startDate` を残し、`updated` を同じ値で補った | 2 | advancedjs、anthropology-react |

5. **以後、V2の notes は全件が二日付。** 抜き取りで確かめた6時点（2021-10-31、2021-12-31、2022-06-30、2022-12-31、2023-12-31、2024-11-30）すべてで、notes の全件（60〜76本）が両方の日付を持っていた。

## 2｜この観測が意味すること（四層に分けて）

| 層 | 内容 |
| --- | --- |
| 原稿 | 42本では、V1の単一の日付（V1の表示では Last tended）が、V2で Planted と Last tended の両方の値になった |
| 現在 | V3でも、確認した babel・compilers は「startDate = updated = 旧単一日付」のまま。neologisms は後に 2020-11-01 へ書き換えられている |
| 表示の推論 | これらのノートの現在の Planted は、植えた日の記録ではなく、一括付与のときに写された値である可能性が高い |
| 著者の意味づけ | 判定できない |

標本01の「現在のスキーマで過去を読み替えない」は、ここで一本の木の注意から、庭の半分以上に関わる注意になった。現在の画面で Planted と Last tended が同じ日付のノートを見ても、「植えたあと手入れしていない」とは読めない。

## 3｜留保と次の地層

- essays へ移った18本の、その後の日付の変化は未集計（3本は取り込み時に `updated` を失っている）。
- 「両方新規」型の3本の値（2020-01-01 など）は、仮置きの値に見えるが、意図は判定しない。
- V2とV3の対応づけ、V3での `publication-schemas.mjs` による必須化の時期は未調査。
- 重なり期間に V1 と V2 のどちらが公開されていたかは、Gitでは決まらない（デプロイの層）。

## 4｜仮説の欄（事実ではない）

- V1で二日付になっていたのは、手をかけて書き直していた原稿が多く、それが V2 で essays として扱われた、という読みはありうる。ただし、「二日付化」と「essays への移動」の相関を観測しただけで、理由は確認していない。
